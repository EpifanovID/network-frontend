# Локальный запуск и подготовка данных

## Что нужно заранее

- Node.js версии 20.19+ в ветке 20.x или 22.12 и новее, npm и зависимости проекта. Для установки по файлу блокировки выполните `npm ci`.
- PostgreSQL с доступной базой IMC. Скопируйте `.env.example` в `.env` и задайте `DATABASE_URL`. Для работы без интернета база должна быть локальной. Файл `.env` исключён из Git.
- Для запуска вместе с картой нужны `public/maps/network-overview.pmtiles`, `public/maps/network-areas.pmtiles`, три файла GeoJSON, локальные шрифты и спрайты. Архивы PMTiles хранятся отдельно от Git.

## Запуск без интернета

1. Запустите PostgreSQL.
2. Из корня проекта выполните `npm start` или откройте `start-local.cmd` на Windows.
3. Дождитесь сообщения `Local application listening on http://127.0.0.1:4173` и откройте указанный адрес. Для остановки нажмите Ctrl+C в терминале.

`npm start` сначала собирает интерфейс, затем запускает Express. Если `dist` уже содержит актуальную сборку, можно запустить `node server/index.js --serve-frontend`. Этот режим использует `127.0.0.1` и порт `LOCAL_PORT` (по умолчанию 4173). Для запуска нужен HTTP-сервер.

Приложение читает карту, шрифты, спрайты и данные сети с локальных источников. Интернет может понадобиться при установке пакетов, скачивании картографических исходников и подготовке архивов.

## Режим разработки

В двух терминалах запустите:

```powershell
npm run dev:api
```

```powershell
npm run dev
```

По умолчанию API слушает `127.0.0.1:3001`, а Vite перенаправляет туда запросы `/api`. Если измените `API_HOST` или `API_PORT`, согласуйте адрес в `vite.config.js`. Режим `npm run preview` сам по себе API не запускает. API предназначен для локального доступа и работает без аутентификации.

## Подготовка PostgreSQL

Для новой пустой базы создайте базу, например `imc_db`, настройте строку подключения и запустите `npm run db:migrate`. Для базы с готовой схемой IMC используйте `npm run db:migrate -- --existing-schema`. Последняя команда добавляет таблицу координат `imc.network_node_locations`. Полный комплект миграций рассчитан на владельца базы с правами на создание расширений и объектов, в том числе с владельцем `postgres`.

Для чтения графа учётной записи приложения нужен доступ на чтение таблиц IMC. Для вызова API записи координат нужны права `SELECT`, `INSERT` и `UPDATE` на таблицу координат. Импорт и демонстрационное наполнение запускайте учётной записью с правами на запись соответствующих таблиц.

Миграции создают структуру. Если нужен исходный набор XML IMC, подготовьте пустую схему и резервную копию базы:

```powershell
npm run db:import -- --seed-dir "C:\path\to\imc_init\init_files" --config "C:\path\to\imc_init\config\imc_init_config.xml"
```

Импорт выполняется в транзакции, пропускает справочники, которыми управляет база, и останавливается, если целевые таблицы уже заполнены. Исходный набор XML может содержать учётные записи и хеши паролей. Храните его отдельно от проекта и используйте штатный импорт проекта. Прежний инициализатор из поставки IMC записывает пароль базы в журнал.

Для подготовленной демонстрационной базы доступны команды `npm run db:seed-demo-nodes` для примера УС4–УС9 с линиями и `npm run db:seed-node-classes` для заполнения отсутствующих классов A/B/C. Скрипты используют существующие шаблоны IMC. Отдельный `node scripts/seed-demo-network.js` добавляет расширенную демонстрационную сеть на основе записи УС1. Проверяйте, на какую базу указывает `DATABASE_URL`, перед запуском команд наполнения.

## Подготовка карты

Для Windows используйте Git, Java 21+ и Maven. Скрипт ищет Java и Maven в `PATH` и в каталогах `tools\jdk` и `tools\maven` внутри каталога сборки. На диске сборки ориентируйтесь минимум на 35 ГБ свободного места после загрузки исходников.

```powershell
.\scripts\build-offline-map.ps1 -BuildRoot D:\NetworkMapBuild -OverviewOnly
.\scripts\build-offline-map.ps1 -BuildRoot D:\NetworkMapBuild
```

Запускайте команды последовательно. Первая создаёт обзорный архив до масштаба 8. Вторая собирает детальные данные до масштаба 15 в зонах радиусом 25 км вокруг сохранённых координат. Скрипт берёт исходные данные OpenStreetMap из выгрузки Geofabrik, использует сборщик Protomaps и сохраняет результат в `public/maps`. После изменения координат детальный архив нужно пересобрать для обновления покрытия. При запуске из `cmd` используйте `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\build-offline-map.ps1"` с теми же параметрами.

Для пересборки GeoJSON используйте `npm run build:military-districts`, `npm run build:russia-regions` и затем `npm run build:russia-outline`. Подробнее об источниках и лицензиях см. [атрибуцию карты](../public/maps/ATTRIBUTION.md).

## Проверка запуска

- По адресу <http://127.0.0.1:4173/api/health> ожидается JSON с полями `"status": "ok"` и `"database": "connected"`.
- Если сервер сообщает `Missing local file`, проверьте исходный ресурс и заново выполните `npm run build`. Если порт занят, остановите предыдущий сервер или задайте другой `LOCAL_PORT`.
- Если API работает, а объекты отсутствуют на карте, проверьте координаты в ответе `/api/graph`. Если не хватает детализации, проверьте наличие PMTiles и покрытие.
- При переносе на другой компьютер заранее подготовьте зависимости, оба PMTiles и остальные ресурсы карты. Базу переносите резервным копированием и восстановлением PostgreSQL. Параметры подключения задайте в локальном `.env`.
